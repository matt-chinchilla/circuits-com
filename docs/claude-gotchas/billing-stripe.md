## Gold/Platinum sales + rep billing console (2026-09-23, migration 057)

Spec `docs/superpowers/specs/2026-09-23-gold-platinum-sales-design.md` (v2: rulings R1–R17, owner decisions D1–D10), plan `docs/superpowers/plans/2026-09-23-gold-platinum-sales.md`. This section records what was BUILT, checked against the code at `sales/integration` 1c882cb; where a seat's ruling departs from the spec, the text says so.

- **The ONE price rule — `api/app/services/sales_pricing.py`** — nothing else computes a sponsorship price, and the browser renders only numbers the server returned. `price_usd(tier, code_points) = max(floor_usd, founder_usd − ceil(code_points × list_usd / 100))`, whole dollars. `list_usd = QUOTE_LADDER[tier][0]` (250 / 2,500 / 10,000; `stripe_quotes.QUOTE_LADDER` stays the list price's single home). `FOUNDER_USD = {"silver": 210, "gold": 2100, "platinum": 8500}` is the named **Founder's Deal**, charged FOREVER (D5/D8) and shown by that name on /join, the receipt and Stripe invoices; there is deliberately NO `FOUNDER_PRICING_ENABLED` flag (R17 — a flag could silently raise a Founder customer on the next discount change). `floor_usd = list × 70 // 100` (175 / 1,750 / 7,000): no path discounts more than 30% off list in total (D2/D9). `MAX_CODE_POINTS = 15`. Pinned values: Silver 0 → 210; Gold 0 → 2,100, 10 → 1,850, 15 → 1,750 (the floor); Platinum 10 → 7,500, 15 → 7,000. `code_points` must be a plain int 0..15 (a `bool` is refused — a JSON `true` must never read as one point); the tier is case- and space-insensitive. The price is charged through ONE `amount_off`, `duration: forever` coupon per price: id `coupon_id()` = `{TIER}-AT-{price}` (e.g. `GOLD-AT-1850`), name `coupon_name()` = `"{Tier} Founder's Deal — ${price:,}/mo"`, minted by `stripe_quotes.ensure_price_coupon(client, tier, target_usd, product_ids, name=)` (guard `0 < target < list`; fence = the resolved prices' products; reuse rules in the quotes entry above).
