- **Stripe live objects (account `acct_1U0vY1DqTxm052QN`; REPRICED 2026-08-22)** — 6 products/6 monthly prices, lookup_keys `<tier>_{advertising,platform}_monthly`, 90/10 ad/platform split per tier (**Silver $225+$25=$250, Gold $2,250+$250=$2,500, Platinum $9,000+$1,000=$10,000**; was 100/600/2400 until 2026-08-22 — those six price objects are ARCHIVED, and existing subscriptions still hold them, so current sponsors stay at the old rate until migrated). **`unit_amount` is immutable — repricing means NEW price objects created with `transfer_lookup_key=true`, then archiving the old ones; never try to edit an amount.** The 90/10 split is load-bearing TAX structure, not cosmetics: it is what keeps the advertising line `product_exempt` under NY's primary-purpose test, tax codes txcd_10701000/txcd_10103001, **`tax_behavior: INCLUSIVE`** (recreated same day — the sticker IS what the customer pays; Stripe backs NY tax out of the platform line by customer location; the first `exclusive` set is archived with lookup keys TRANSFERRED — `tax_behavior` is immutable once set, replacement is the only path). A sale = ONE subscription carrying BOTH of the tier's prices. On inclusive prices **amount_off coupons land on exact round totals** (the ladder mechanism); the two live 50%-forever percent coupons are named for their PERCENTAGE, not a dollar figure, so a reprice rescales them automatically — post-2026-08-22 they land on $1,250 Gold / $5,000 Platinum, both real `QUOTE_LADDER` floors. Never stack discounts (percentages multiply). NY state_sales_tax registration is active in Stripe Tax (head office Lake Ronkonkoma); Stripe collects only if the subscription/invoice/quote sets `automatic_tax`. **Verified tax math (2026-08-15, live `tax/calculations`)**: Lake Ronkonkoma buyer → at the 2026-08-22 prices, $2.01 of the $25 Silver platform line is NY tax (8.75% Suffolk; advertising line `product_exempt`), total pinned at $250 (pre-reprice it was $0.80 of $10, pinned at $100); NJ buyer (even WITH a registration) → `product_exempt` on BOTH lines, $0 — NJ exempts advertising AND doesn't tax SaaS. Hosted checkout shows "Enter address to calculate" until the buyer types one — tax is DESTINATION-based (buyer's county, not seller's state; NYC 8.875% ≠ Suffolk 8.75%), computed pre-payment; inclusive pricing means the address only changes the revenue/tax SPLIT inside the sticker, never the total. `tax/settings` defaults are `tax_behavior=inclusive` account-wide (set 2026-08-15 — a future price created without an explicit behavior can't silently break sticker-pricing); default tax_code `txcd_10000000` is fallback-only (both products carry explicit codes). COMPLIANCE THE CODE CAN'T ENFORCE: a Stripe registration is a DECLARATION of a real state registration (NY Certificate of Authority DTF-17 — CPA verifies), NY requires a return EVERY period once registered (even $0 periods), and Dashboard→Tax→Monitoring watches economic-nexus thresholds for expansion — register with the STATE first, then add it in Stripe.

- **Sales quotes from /admin (`services/stripe_quotes.py` + `routes/admin_quotes.py` + `sponsors/form/QuotePanel.tsx`)** — rep opens an EXISTING sponsorship → "Stripe billing" panel → fixed ladder of ALL-IN monthly prices (`QUOTE_LADDER`, single home, first entry = list) → server find-or-creates the customer, mints the `TIER-AT-<n>` amount_off coupon lazily, creates+finalizes the quote (`automatic_tax`, `send_invoice`/30d, `subscription_data.metadata.sponsor_id` = the webhook linkage, quote `metadata.sponsor_id`+`managed_by`) and **verifies `amount_total == target` or cancels** (cancel wrapped: a failed cancel must not mask the mismatch — error names the still-open quote id). Learned the hard way, all reviewer-confirmed: **query strings ONLY via httpx `params=`** (an f-string ships `+` raw → Stripe decodes a space → plus-addressed billing emails mint a DUPLICATE customer per quote and the list goes blank forever; `&`/`#` in an EmailStr-valid address inject/truncate); **customers are per-supplier via `metadata.supplier_id` match, never email-only** (shared AP inboxes are real; email-match overwrote the other company's identity); **quote list is sponsor-scoped by quote metadata** (a supplier holds many placements on ONE customer — unfiltered, "Customer accepted" on page A activates board B); **coupon reuse verifies amount AND duration AND currency** (Stripe defaults duration to `once`: right amount, first invoice only, renewals silently revert to list); **no per-quote email override** (create keyed on override + list keyed on file = unacceptable quotes; billing identity lives on the supplier record); accept re-checks `managed_by` before committing; QuotePanel prices off the PERSISTED tier, not `form.tier` (choosePlacement rewrites unsaved state). Panel hides when `STRIPE_SECRET_KEY` unset (routes 404, demo-door posture); demo refused on READS too (`demo_account_no_billing` — quote PDFs are customer billing docs). Guard: `test_stripe_quotes.py` (FakeStripe MockTransport that FILTERS on query params — a fake that ignores the query certified the encoding bug green).

- **Stripe webhook receiver (`routes/stripe_webhooks.py` + `services/stripe_webhook.py`)** — POST `/api/stripe/webhook`, hand-rolled HMAC (NO stripe SDK — the app only consumes events): sign over the header's own `t` STRING + raw body bytes; length-bound `t` ≤20 digits BEFORE `int()` (CPython ≥3.11 ValueError past 4,300 digits = pre-auth 500); tolerance is ONE-SIDED old-only like Stripe's SDK (an `abs()` check kills all billing when the box clock runs slow). `STRIPE_WEBHOOK_SECRET` unset → route 404s (demo-door posture) — **which MASKED a real gap for 3 days**: prod `.env` NEVER held any `STRIPE_*` var until 2026-08-14 night (checkout + webhook silently 404 since the 2026-08-11 deploy; /pricing showed its desk fallback and nobody noticed). Fix: keys piped dev-`.env`→prod-`.env` over ssh (values never transit a transcript), endpoint `we_1U4WbrDqTxm052QNt6qH7IUn` registered for the 4 handled events, then api+cost-sync `up -d --force-recreate` (`restart` won't re-eval `${VAR:-}`). LESSON: after any deploy touching key-gated features, PROBE the gated endpoints (`GET /api/checkout/silver` → 200; unsigned webhook POST → 400, NEVER 404) — a 404-by-design posture reads as healthy to every ordinary check. Map: `invoice.paid`→Active, `customer.subscription.deleted`→Expired, `invoice.payment_failed`→LOG ONLY (grace period undecided). Sponsor resolved via subscription metadata `sponsor_id` (sales MUST stamp it; invoice events carry it at `parent.subscription_details.metadata` (2025+ API) or `subscription_details.metadata` — both read). Three write-gates, all ack 200: event `created` older than `sponsors.updated_at` → skipped (replay/out-of-order must not resurrect a deliberate Expire); Paused is NEVER un-paused by billing (admin visibility lever, `'Active'|'Paused'|'Expired'`); IntegrityError from migration 016's indexes → rollback + `slot_conflict` (rollback is load-bearing: without it the post-conflict logging raises PendingRollbackError → 500 → Stripe retry spiral → endpoint auto-disabled). Unactionable payloads (unknown sponsor, bad uuid) ALWAYS 200 — a non-2xx makes Stripe retry for days then disable the endpoint. OPS RULE: cancel subscriptions WITH "void open invoices" — a final invoice paid after cancellation is a NEWER event than the Expire and legitimately re-activates (documented residual; complete fix = processed-event ledger or liveness check). Guard: `test_stripe_webhook.py` (37; slot conflict is ORGANIC — SQLite supports partial unique indexes, recreate 016's predicate rather than monkeypatching commit; test fixture is a KEYWORD sponsor because seeded_db's NULL-status Gold already holds the child's slot and NULL counts as active in the index).

- **Automated cost sync (`services/cost_sources/` + `jobs/sync_costs.py` + the `cost-sync` compose service)** — real spend replaces the hand-typed Cost Breakdown. Sources: AWS Cost Explorer (ONE GetCostAndUsage/day grouped by the `Application` cost-allocation tag — us-east-1 only, **$0.01/request**; vendors `AWS - Circuit Center`→infrastructure, `AWS - Mail Server`→**email** (user decision: per-server price comparison at category level), untagged→`AWS - Other`→infrastructure), Stripe fees (free API, every hourly pass; count `fee` PLUS `type='stripe_fee'` rows' negative `amount` — Billing/Tax bill that way and `fee`-only missed them), Anthropic (stub; needs `ANTHROPIC_ADMIN_KEY`, allowlisted ONLY on cost-sync — an org-admin secret must not ride the internet-facing api container). Schedule: hour-ALIGNED ticks (`sleep` to the boundary), AWS gated one-sync-per-ET-day → the **00:00 ET tick is the daily report**; operator levers `--once --force-aws [--months N]` (N = post-backfill full re-read). Write rules (`upsert_synced_costs`): match (source, vendor, period_start); NEVER touch `source='manual'`; any REAL source supersedes `estimate` rows in its category+month (seed's AWS/Stripe/Anthropic/Hover PLACEHOLDERs are all `estimate` — migrations 026/027 backfill prod); `reconcile_source=` deletes same-source rows the snapshot stopped reporting (zero-ratchet: a credited-to-zero month must lose its row) — skipped on empty snapshots. **Editing a synced row PROMOTES it to `manual`** (human takes ownership, sync stops touching it); **DELETE of a synced row is 409** (it would be re-created within the hour). **Mail carve-out**: pre-tagging months where the box existed (born 2026-08-01, `MAIL_SERVER_LAUNCHED`) get an `estimate` email line prorated at $0.35/day CARVED OUT of `AWS - Other` (total stays the invoiced truth; capped at what Other holds; skipped when a tagged mail actual exists). Tag activation is forward-only (2026-08-11); a `start-cost-allocation-tag-backfill` was filed same day — after it completes, `--once --months 13` re-reads history. Prod credentials = EC2 instance profile `circuits-cost-explorer-read` via IMDS (hop limit 2 for containers — already set); dev = `~/.aws` mounted ro on cost-sync only. **`deploy.sh` must name cost-sync in BOTH build lists** — `up -d` alone never rebuilds an existing image, and the job would run first-deploy code forever. `/dashboard/expenses/breakdown?month=YYYY-MM` + `available_months` (desc, cap 24) feed the panel's month pager (`monthPager.ts` steps the LIST — months can be non-contiguous); `estimated` flag is per-response row data, never the static category meta. Guards: `test_cost_sync.py`, `test_expenses_breakdown_months.py`, compose passthrough tests.
