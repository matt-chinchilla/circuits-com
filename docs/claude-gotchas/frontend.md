# Frontend rendering, prerender & assets — full gotcha histories

Moved verbatim from CLAUDE.md 2026-08-28 to cut per-session context cost. The
compressed rule (same bold key) lives in CLAUDE.md's Gotchas section; this file
holds the full story — evidence, measurements, dates, refuted hypotheses.
**Update BOTH files when a rule changes.**

- **"Animations frozen right after a deploy" ≠ a code regression — suspect a STALE CACHED BUNDLE first (2026-06-22)** — a user reported BOTH Platinum csFx + Gold flashlight "deleted" immediately after a deploy; the real cause was their browser still running the pre-deploy content-hashed bundle (tab left open across the deploy — see the `vite:preloadError` gotcha). A **HARD REFRESH** (Cmd/Ctrl+Shift+R) fixed it; ZERO code change was needed. **Diagnose BEFORE reverting** (don't reflexively rip out a real fix on a user report): (1) multiple INDEPENDENT effects dead from a SINGLE-FILE change ⇒ a shared/client cause, not that file (the csFx fix never touched the Gold flashlight); (2) MEASURE the live site, don't guess — full-canvas pixel-sample the csFx `<canvas>` across ~24 frames (`getImageData` sum-delta over `requestAnimationFrame`); a small/corner sample MISSES the sparse directional shimmer → false "static" (a 200×200 corner read = delta 0; the FULL canvas = 1754 = animating); (3) check `matchMedia('(prefers-reduced-motion: reduce)').matches`.

- **Fixed-angle 3D *decoration* = ONE vector `<svg>`, NOT CSS-3D `preserve-3d`** — preserve-3d is O(faces) GPU layers (the login board was ~210); at the iPhone's **DPR 3** pinch-zoom re-rasters them all → WebContent **OOM crash + auto-reload**, and the per-frame composite **flickers** once animating. SVG = O(1) layer (vector-crisp at any zoom, no flicker). Login `IsoBoard`: **desktop CSS-3D** (`IsoBoard.tsx`, has the headroom at DPR 1–2) / **mobile `<svg>`** (`IsoBoardSvg.tsx`, ≤900px) — BOTH project the SAME `isoGeometry.ts` (orthographic iso `sx=.707(x+y)`, `sy=.395(y−x)−.829z` ≙ CSS `rotateX(56)rotateZ(−45)`; a horizontal circle → axis-aligned ellipse `ry=r·cos56`, used for the cap). `transform: scale()` is **visual-only** (shrinks neither layout box NOR GPU backing store) → mobile scale-down cuts ZERO GPU cost; page-fit via grid `minmax(0,1fr)` (NOT `1fr`=`minmax(auto,1fr)`, which the fixed-px board inflates past the viewport). NEVER `will-change`/`overflow:clip` a preserve-3d/perspective node on mobile (DPR² layer-pin OOM / flatten / chip-crop). SVG @keyframes live in the sibling PLAIN `LoginPage.keyframes.scss` (CSS-Modules hashes @keyframes even inside `:global`).

- **Category page = opacity-only fades** — breadcrumb `fade-in-up`/`useEntrance` were REMOVED because they re-fired on every subcat remount and read as jitter; do not add entrance animation here. Sibling subcat nav renders breadcrumb/title/chips SYNC from `@public/services/categoryShellMemo.ts`, so only parts and counts load. Four layout invariants: `.chips` has NO `margin-top` (parent/child/skeleton subnav heights must match or the banner snaps); **busy skeletons MUST reserve REAL heights** (title/meta 42/24px, subnav = 6 wrapping pills) because the banner paints instantly above them; **NEVER `min-height` on the flex `.chipBar`** (`align: stretch` balloons a single row's chips on wide screens); chips are `<button>` (JS-nav), not `<a>`. Parts + counts are cached in `@shared/services/categoryDetailMemo` (**LRU cap 12** — each entry holds ≤500 parts and unbounded is a mobile-heap problem), read SYNC in CategoryPage's `useState` initializers so a revisit paints on the FIRST frame, revalidating in the background; `bustSponsorCaches()` must also call `clearCategoryDetailMemo`. **Part mutations — `createPart`/`updatePart`/`deletePart` AND `batchImportParts` — MUST wrap `bustingAfter`** in `adminApi`, or counts and SKUs go stale.

- **Wizard at `@admin/wizard/`** — `data-tour=`/`data-field=`/`[data-modal=]` anchors; guard `api/tests/test_wizard_data_anchors.py`. `useAdvance` keeps route-based and polling-based effects SEPARATE — combining them hung Step 1→2. **Advance is COMMIT-not-keystroke**: it fires on blur/Enter/Next or a ~1.5s stable settle (`VALUE_SETTLE_MS`), NEVER while the input is focused and changing — firing at the min-length test made every typing step auto-jump mid-name. **Demo cleanup is DEMO-marker-guarded**: `cleanupDemoEntity` FETCHES the entity and refuses to delete unless it bears the marker (`DEMO_SUPPLIER_NAME` 'Demo Components Inc.'; part/listing sku `startsWith('DEMO-')`), so real catalog data is undeletable by construction rather than by correct tracking. `goBack` records its guard against the goto LANDING route, not the leaving route, or a route step dead-ends. Spotlight: `useTargetRect` rounds+dedups the rect (ONE retry chain) and `.spotlight`/`.coach` use 170ms ease-out, not a 320ms overshoot — do not reintroduce the per-tick `setRect` churn.

- **Stale lazy-chunk after deploy → `vite:preloadError` recovery reload** — lazy routes (App.tsx) are content-hashed chunks; a deploy deletes the old hashes, so a returning client on a pre-deploy `index.html`/module graph (most often a tab left open across the deploy) dynamic-imports a 404'd chunk → `import()` rejects → ErrorBoundary "failed to load" dead-end until a manual browser-cache reset (eager `HomePage` is immune; every lazy route was affected — it's not contact-specific). `@shared/preloadErrorRecovery.ts` (called in `main.tsx` BEFORE render, bundled in the EAGER entry chunk) turns `vite:preloadError` into ONE `sessionStorage`-guarded recovery reload — fail-open if storage throws (Safari private mode / locked-down browsers), whole install `try/catch`-wrapped so a hardened-browser `window.sessionStorage` throw can't white-screen bootstrap. Don't remove the `installPreloadErrorRecovery()` call. Guard: `frontend/src/shared/preloadErrorRecovery.test.ts` (vitest, 5 tests).

- **The company logo is `@shared/components/Logo` — per-size OPTICAL BANDS, not one master scaled (2026-08-03)** — "The Master" (design 13a): a capacitor in the counter of a C whose right terminals are the feet of an Ω. Stroke weights CHANGE per size band (arc 24→22, electrodes 10→9) and **at 16px the ground stem is dropped entirely** — three electrodes plus a stem cannot survive 16 device px. Do NOT collapse the bands into one geometry + transform; that is what they exist to avoid. Two variants: `badge` (own dark plate) / `mark` (glyph-only, for already-dark surfaces). **The badge's hairline rim is load-bearing, not decoration**: the plate `#1a1f23` measures 1.14:1 vs steel's bar, 1.06:1 vs schematic, 1.30:1 vs pcb — invisible by fill on every dark surface, so the square reads by its EDGE. Used in navbar, admin sidebar, admin login, public footer (each replaced a pre-logo stand-in: a CSS dot/square lockup, a letter "C" tile, a pulsing dot, nothing). Favicon ladder is per-size PNGs (16/24/32/48/180) with **NO `favicon.svg` on purpose** — browsers prefer an SVG icon over every sized PNG, discarding the tuning.

- **The site is PRERENDERED — every route serves its own HTML (2026-08-03)** — `frontend/scripts/seoPrerender.ts` (a Vite plugin) writes **one static document per manifest route** at build (3,709 at launch; ~12k by 2026-08-21): home, the static pages, categories, subcategories, and parts. **OPEN DECISION (2026-08-21): prod holds 132k+ parts — a 1:1 part prerender is ~2GB of dist; a cap/tier rule is REQUIRED before the next seo-manifest regen.** Before this, EVERY url returned one byte-identical 6,659-byte shell (md5 `8969a91a68a2` across `/`, `/about`, `/category/*`, `/keyword`) — same `<title>`, no canonical, no `<h1>`, no JSON-LD — because all SEO ran client-side. Affordable ONLY because `renderRoute` is regex replacement over the built shell, **not React SSR**: cost is file writes, so build 12s→20s and dist 6MB→48MB, with zero bytes added to any JS chunk and no Node in the request path. Route data comes from `frontend/seo-manifest.json`, a **COMMITTED snapshot** (the Docker build stage has no network/DB) — regenerate with `node scripts/gen-seo-manifest.mjs [api-base]` after a reseed or new parts, or new rows silently fall back to the generic shell. `/api/parts/` caps `per_page` at **100** (the 500 ceiling is the CATEGORY endpoint). Home writes to `home.html`, NOT `index.html` — `index.html` stays the generic fallback, and baking home's canonical into it would make every uncovered URL declare `rel=canonical → /`. **nginx `try_files $uri/index.html` is what makes any of it reachable** — drop it and every URL silently reverts to the shell with no build or test failure; guard `api/tests/test_nginx_seo_prerender.py`.
