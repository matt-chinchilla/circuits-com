# Deploy, reseed & seed identity — full gotcha histories

Moved verbatim from CLAUDE.md 2026-08-28 to cut per-session context cost. The
compressed rule (same bold key) lives in CLAUDE.md's Gotchas section; this file
holds the full story — evidence, measurements, dates, refuted hypotheses.
**Update BOTH files when a rule changes.**

- **`./deploy.sh --reseed` destructive scope** — TRUNCATEs `sponsors, category_suppliers, categories, suppliers CASCADE`; **TRUNCATE CASCADE is TABLE-level and transitive, ignoring ON DELETE entirely** — and ON DELETE governs a later delete of a referenced ROW, doing NOTHING for an INSERT that names a row which no longer exists (until 2026-08-25 this bullet claimed `created_by_id` being SET NULL made the calendar restore "a straight load"; measured on the real schema, that load died on `calendar_events_created_by_id_fkey` with psql exit 3 and restored ZERO events, because the seed re-mints every user uuid). The cascade reaches users/parts/listings/breaks/revenue/supplier_feeds/calendar_events(+sends)/messages/bom_shares/activity_events. `deploy_reseed` now carries FIVE things by hand, and **ORDER is the design: `users` is restored BETWEEN the TRUNCATE and the seed** — `_seed_admin_user` keys on username, so it ADOPTS the restored staff rows (uuids/bcrypt hashes/roles intact) and CUSTOMER accounts, which the seed NEVER recreates (the census once declared `users` "reseeded from source"; false — a reseed destroyed every registered customer), come back whole. Because users keep their uuids, the after-seed restores of calendar/messages/bom_shares keep attribution and user_ids for real — their NULL-where-unresolvable guards are a race safety net, not the mechanism. `users.supplier_id` is NULLed at restore (suppliers is empty at that instant) and relinked BY NAME after the seed; `supplier_feeds` cannot ride pg_dump at all (supplier_id IS its PK and every supplier uuid changes) so it travels as a (supplier name, config) TSV re-keyed onto the reseeded suppliers — without that, every nightly auto-import toggle silently turned OFF and every import cursor died. A full `-Fc` safety dump lands at `/tmp/pre-reseed-safety.dump` first (one-deploy-cycle undo for the accepted losses). Still destroyed deliberately: `activity_events`, every feed-imported part the catalog JSON never carried (~171k on prod — think hard before a prod `--reseed`), and admin-UI rows outside seed.py. Guard: `test_leads_schema.py`'s census walks the ENTIRE metadata cascade and pins the deploy.sh dump/restore ordering.

- **The fictional demo catalog is flag-gated — `SEED_DEMO_CATALOG` (2026-08-18)** — the entrypoint re-seeds on EVERY api container start, so deleting a demo company ("Kennedy Electronics", "Mike's Electric") in /admin on prod was undone by the next deploy, forever. Code default **True** (local/dev seeds the 7 fictional suppliers + Kennedy's Platinum/Gold showcase sponsorships); **prod compose defaults it false** so prod seeds the REAL catalog only and an owner's deletion STICKS. The flag never deletes anything — seeding is get-or-create, it just stops resurrecting. Every dependent reference is guarded (`suppliers.get(...)` + `_drop_absent_suppliers()` on the shared association lists + `if kennedy is not None` on the sponsor blocks): an unguarded `suppliers["Kennedy Electronics"]` KeyErrors inside the entrypoint = prod 502-loop. Unsold boards then render their designed Open-Placement state. The wizard's separate 'Demo Components Inc.'/`DEMO-` marker is UNRELATED. Guards: `test_seed_demo_flag.py`, `test_compose_env_passthrough.py`.

- **Leads CRM (2026-08-20, migration 036)** — admin-only sales tooling: `manufacturers` (2,452 = breakdown CSV ∪ catalog names, canon-merged) + `manufacturer_aliases`/`_merge_candidates` (review queue, NEVER auto-applied) + `leads` (359 people/placeholders) + `lead_contacts` (append-only outcomes, `recorded_by` free-string). **FK DIRECTION IS THE RESEED SAFETY**: no CRM table references the TRUNCATE graph; the only bridge is `suppliers.manufacturer_id` (SET NULL, partial-unique) — guard `test_leads_schema.py`. Sponsorship = promote/link to a Supplier row; slot machinery untouched. `app/services/manufacturer_canon.py` is the SINGLE canon home (contract pairs in its test — `Microchip USA` ≠ `Microchip Technology` is load-bearing). Leads are NEVER public: own routers, demo REFUSED ON READS (`demo_account_no_leads`, dashboard feed included), `manufacturer_id` in neither `supplier_to_dict` nor `SupplierResponse` — guard `test_leads_never_public.py`. Frontend: `/admin/manufacturers` ↔ `/admin/leads` behind the centered CatalogSwitch (two REAL routes); outcome trio `#153f80/#4d189e/#b91c1c` + word + glyph (NEVER `#2563eb`+`#7c3aed` — chartTheme CVD constraint); `OUTCOME_META`/`firstInitial` single home `pages/leads/outcome.ts` (placeholder rows get a dot, never a fake initial).

- **Seed catalog probe is ONE bulk key-set, never per-row (2026-08-20, 11.9s→1.0s/start)** — `_seed_real_catalog` loads `existing_skus` via a single `Part.sku.in_(json keys)` query; the old per-row `.first()` hydrated the `lazy="selectin"` listings+breaks cascade (~209k discarded ORM objects = 93.8% of every container start). TWO load-bearing invariants: the bulk SELECT stays INSIDE `_seed_real_catalog` AFTER `_seed_parts` (autoflush=False + 17 demo/catalog SKU collisions — hoisting it recreates dupes → entrypoint 502-loop), and every created sku is ADDED to the set (the JSON carries 77 duplicate rows). Create path attaches listings/breaks via relationships (no per-row flush). `scripts/catalog_load.py` now keys on **sku alone** (was `(sku, manufacturer)` — dup-mfr spellings made second rows); key unification was the prerequisite for a unique key, which LANDED 2026-08-23 as `UNIQUE(manufacturer_id, upper(sku))` — NOT `UNIQUE(sku)`, which would have been wrong (49 real MPN pairs span different manufacturers).

- **NEVER rename a seeded supplier in /admin — it FORKS the row (2026-08-24, observed twice)** — `seed.get_or_create_supplier` keys on `Supplier.name`, so a rename does not move the row: the next container start re-creates the original name beside it. Renaming Digi-Key Electronics → "Digi-Key" left TWO rows, and because `registry.match_provider` keys on a `Supplier.website` domain FRAGMENT, both matched `digikey` — a feed run would have written real prices onto whichever the query returned. The same fragment also matched `DigiKey Marketplace` (`digikey.com/marketplace`), which is third-party sellers at different prices. Fix a supplier's name in `seed.py`, never in the admin. Guard: `test_provider_supplier_identity.py` pins both halves (one seeded supplier per provider fragment, and every `provider.supplier_name` must be a name the seed creates — `_get_or_create_supplier` CREATES on a name miss, so a provider whose name differs by one word mints a duplicate). Mutation-verified. The seed's update branch only backfills contact_role/coverage_hours/brand_* — `logo_url` and `website` edits made in /admin DO survive a reseed, as long as the NAME is untouched.
