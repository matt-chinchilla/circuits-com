# Mail server, Roundcube & calendar — full gotcha histories

Moved verbatim from CLAUDE.md 2026-08-28 to cut per-session context cost. The
compressed rule (same bold key) lives in CLAUDE.md's Gotchas section; this file
holds the full story — evidence, measurements, dates, refuted hypotheses.
**Update BOTH files when a rule changes.**

- **Webmail palette = D1 "Instrument Dark" — the fatigue driver is HALATION and CHROMA, not contrast** — the old gold-on-green skin passed every WCAG check and still hurt: pane-vs-bench ΔL* **74.5**, shell chroma C* **19.9**. D1 lands **7.1 / 2.5** using only logo colours (`#1a1f23`/`#ffffff`/`#44bd13`, gold demoted to trim; green carries pad rim, unread dot, focus, selection). Contrast is a GATE (4.5 floor), not a ranking — don't "improve" it. Measure a token on the WORST surface it is USED on: `--cc-dim` read 5.11 on the bare pane but 4.30 on `--cc-raise`, where six of its sites live.

- **Light→dark CSS migration: every miss is in HOW a value is SPELLED, not whether you looked** — a token/literal sweep catches hexes and misses: porcelain written `rgba(242,245,243,.8)`; an escaped hex INSIDE an SVG data URI (`fill='%234d5f54'` — neither a token nor a literal the parser sees; grep data URIs by hand); dark-ink hairlines only meaningful on a light surface; white used as a SURFACE (`background: rgba(255,255,255,.72)`) vs as a specular highlight; drop shadows tinted with the ink colour instead of black (a shadow stays dark on both themes); and same-specificity selector collisions where the later rule silently wins (`.menu.toolbar a` in two lists killed the white legends). Re-measure every recorded ratio afterwards.

- **Shared calendar (migration 025)** — `calendar_events` has NO owner column (shared IS the default state) + `calendar_reminder_sends` whose `UNIQUE(event_id, kind, channel)` **is** the idempotency arbiter, not the job's bookkeeping. Claim-then-send = at-most-once. An UNDELIVERABLE channel must be filtered BEFORE the claim (no relay, no roster, no SNS topic) or the slot is burned permanently. `email._smtp_send` swallows its own SMTP errors, so a dead relay returns NORMALLY — try/except cannot detect it; it returns a bool and the job reads it. The job has no caller except the `calendar-reminders` compose service (`while true; sleep 300`), and tolerates a not-yet-migrated schema with one warning rather than a traceback every 5 min.

- **`/api/calendar/*` refuses the demo account on READS as well as writes** — `POST /api/auth/demo` hands a real session to any anonymous visitor, so read-open would publish the company's meeting schedule. Two doors: the plugin's shared secret or an admin bearer token. Compare the secret as BYTES — `hmac.compare_digest` raises TypeError on non-ASCII `str` (an unauthenticated 500 on every route), and Starlette decodes headers **latin-1** while `os.environ` is utf-8, so re-encode the header side latin-1 or a non-ASCII secret can never match.

- **The Roundcube skin ships `ui.js`** — loaded from the layout include the skin already overrides, so no upstream template is forked. It adds two controls Roundcube withholds: a compose CLOSE that saves the draft first (Elastic's back button is `data-hidden="big"`; NO event fires on draft-save completion, so `rcmail.set_draft_id` is wrapped — original first — and navigation happens inside it), and a one-click checkbox-mode toggle (Elastic's `toggle_list_selection` is gated on `.active`, which its menu item only gains once something is ALREADY selected — hence the old "All, then Selection" dance; the fix calls Elastic's own function with a detached `.active` element so its `set_pref` still runs).

- **A signature does not appear until compose is HTML — `htmleditor` ships as `0` (plain text)** — the identities were correct all along (`standard=1`, `html_signature=1`, markup stored); a plain-text compose simply has nowhere to put HTML. `roundcube-config.inc.php` sets `htmleditor=1` (NOT `4`, "always except replying to plain text", which drops the signature on exactly the replies that reach a distributor's ticketing system) + `sig_above=true`. Remote images: `show_images=1` ("my contacts"), **never `2`** — Roundcube fetches remote images straight from the sender with NO proxy, so "always" lets any stranger's tracking pixel confirm the address is live. `1` works for self-tests because `collected_recipients`/`collected_senders` default true, and matthew is NOT in his own contacts.

- **Roundcube 1.6 extension facts that fail SILENTLY if you get them wrong** — there is **no `identity_save` hook** (that is the FILE name); the real ones are `identity_form`, `identity_update`, `identity_create`/`identity_create_after`, `identity_delete`. Registering the wrong name logs nothing and the save just proceeds. The identity form is **urlencoded** and `identity_form` receives the FIELD array not the `<form>`, so a plugin cannot add `enctype`, and `'type' => 'file'` is rewritten to `type="text"` at `rcube_output.php:356` — two silent paths to `$_FILES` empty. Uploads go through `rcmail.file_upload` XHR to a registered action (core already does this for `#identityImageUpload` on that page). `wash_html` runs ~19 lines BEFORE `identity_update`, so a plugin-substituted signature is stored **unwashed and byte-identical** (its allow-list is `body, link` and would destroy the markup) — but you must force `html_signature=1`. `identity_update` fires BEFORE Roundcube's ownership check, so plugin side effects must re-verify `get_identity($iid)`. In prefs, a `null` value is a **DELETE**. PHP runs as **www-data**.

- **The image ceiling is the CONTAINER, not `memory_limit`** — roundcube runs `mem_limit: 192m` (~55MB idle) while Imagick inside it reports **917MB** memory / 1.8GB map, because its pixel cache is allocated by the C library and never spends PHP's 64M. Exceeding a cgroup OOM-kills the group — webmail down for everyone, on a 916MB box. So `Imagick::setResourceLimit()` runs before every decode, `getimagesize()` probes header-only first, and JPEG uses a `setSize()` DCT-scaled read. Measured: 4032×3024 → 288×288, **PHP peak 2.0MB**, 1.62s, container 58.8→54.3MB. Order is load-bearing: auto-orient BEFORE `stripImage` (else phone photos land sideways), flatten to white BEFORE JPEG (else transparent PNG → black), re-encode LAST (that is the security boundary — a payload after the JPEG EOI does not survive). Do NOT reuse `rcube_image::resize()` (no setSize hint, GD fallback); DO reuse `rcube_image::props()`.

- **ImageMagick here cannot parse valid SVG — glyphs rasterise through headless Chrome** — the only delegate is internal MSVG, which rejects legal path data (`l3.263-.582` → "non-conforming drawing primitive definition"); several brand marks fail outright. `make-signature-assets.py` lays every glyph on ONE page and takes ONE `google-chrome --headless=new --screenshot`, then slices by arithmetic and asserts the sheet came back at the expected size (a mismatch would silently cut the wrong pixels). Brand paths are extracted once into `signature-brand-icons.json` from simple-icons, never typed — a wrong path renders a wrong logo and nothing announces it. **LinkedIn, Slack, Skype, CodePen, AngelList are absent on purpose**: removed from simple-icons at the owners' request.

- **`sig_social` builds a CROSS-HOST url and can never stat the file** — it validated the slug's *grammar* and emitted an `<img>` regardless, so any label without a mark (Slack, or anything typed) produced a **broken image in the recipient's inbox**, not the text link the design promised. Fixed with `icon_slugs`, generated into `signature-icon-slugs.php` by the same script that creates the files, fed through the company block. An **absent** list means no icons, never all icons — a text link is degraded, a broken image is wrong. Filenames key off `slugify(title)` (`sig_social_slug` ↔ `social_slug`), not simple-icons' own slug: they disagree on dev.to (`devto` vs `devdotto`).

- **`mail/` has a dependency-free PHP test harness** — `php mail/tests/run.php [filter]`, exit 0 only when green. **No composer/PHPUnit ever**: the skin and plugins ride the upstream Roundcube image untouched precisely because nothing there pulls a dependency, and a `vendor/` tree beside bind-mounted code would end that. **Local PHP has no mbstring, gd, imagick or pdo_sqlite** — so clamp with `preg_match('/^.{0,N}/us')` and never `mb_*` (it would fatal the harness while working in the container), and image tests SKIP LOUDLY locally. Run them where the risk lives: `mail/tests/run-in-container.sh`. Mail-box files at `/opt/circuits-mail/` are COPIES, not a git checkout — scp them; Instance Connect keys expire in 60s, so re-push before each ssh/scp.

- **`mail/roundcube-plugins/*/config.inc.php` is gitignored — as of 2026-08-07, and it never was before** — cccalendar's `.dist` header had claimed since it was written that the real file "is gitignored by the repo's rule"; `git check-ignore` exited 1. Nothing leaked only because no such file had been created yet, while that same `.dist` instructs the next person to create one holding `CALENDAR_API_SECRET`. The documentation was not stale, it was never true — which is why re-reading it could not have caught it and running the command did.
