# Circuit Center

Electronic components directory prototype — Vite React SPA + FastAPI + PostgreSQL + n8n, all in Docker.

## Prerequisites
Docker & Docker Compose · Python ≥3.12 · Node.js

## Commands

```bash

docker compose down -v                  # stop + drop volumes

# API (from api/)

pytest tests/ -v                        # ~1,750 tests, SQLite in-memory
```

### Auth model (P1 overhaul, 2026-07-31 — migration 022)
`POST /api/auth/login` takes **`email` + `password`** — email is the ONLY login key (case-insensitive on `lower(email)`, unique via `uq_users_email_lower`); **no username fallback for any account**. `users` also gained `must_change_password` (BOOLEAN NOT NULL) + `password_changed_at` (TIMESTAMPTZ), and the `user_role` enum gained **`owner`**. Accounts: `matthew`, `Anthony`, `Daniel`, `Ronald`, `demo` — all `<name>@circuitcenter.ai`. **022's promotion (matthew→`owner`) + flagging (the 4 staff→`must_change_password`) are a one-time backfill of EXISTING rows** — `seed.py` still creates every admin as role `admin`, unflagged, so a FRESH local DB (migrations run before seed) has neither. Don't "fix" that divergence in seed without deciding what a brand-new environment should do.

- **Password policy** — EXACTLY 8-24 chars, ≥1 uppercase, ≥1 digit, ≥1 symbol. One backend home `app/services/password_policy.py` (`validate_password` → failed rule keys), mirrored 1:1 in `@admin/services/passwordPolicy.ts` (ASCII-anchored on BOTH sides so the JS `[A-Z]`/`\d` can't diverge; length counts code points). 422 body = `{code:'password_policy', message, unmet:[...]}` — the form ticks its checklist off `unmet` (`apiErrorDetail` only surfaces STRING details, so read `detail.unmet` explicitly).
- **Forced reset** — `get_current_user` 403s `password_change_required` for a flagged user; `get_authenticated_user` (no gate) backs the 2 exempt authed endpoints (`GET /auth/me`, `POST /auth/change-password`; `/auth/logout` takes no auth at all). Fail-CLOSED: every admin route already depends on `get_current_user`. Client: `adminApi` response interceptor raises `passwordGate` on that 403 (does NOT clear the token — it's still valid), `ProtectedRoute` redirects to `/admin/change-password`.
- **Session invalidation** — `POST /auth/change-password` stamps `password_changed_at`; `token_predates_password_change` 401s every token minted before it (no revocation table). The route returns a FRESH token so the caller isn't logged out by succeeding.
- **Rate limiting** — `app/services/rate_limit.py`, in-process, two namespaces (`login:*` / `recovery:*`, deliberately NOT shared) keyed per-IP AND per-account: 5 failures → 60s lock, doubling to a 15-min ceiling, cleared by success, decayed after 15 min. Counters are per-worker — the effective threshold multiplies by worker count (single uvicorn worker today).
- **Demo is exempt + credential-less** — `POST /api/auth/demo` (no body) mints a token for `settings.DEMO_LOGIN_EMAIL`, so no password ships in the JS bundle; it 404s (never 403) when disabled/missing. The demo email is REFUSED by `/auth/login` (`_is_demo_identifier`) — a public password that legitimately succeeds would also clear an attacker's own rate-limit lock. Demo is never flagged `must_change_password`. UI = the secondary "See Demo →" button on the sign-in screen.
- **Anti-enumeration is load-bearing** — unknown account → `verify_dummy_password()` (timing equalized) + the SAME counted failure + the same generic 401; recovery endpoints always return the generic OK. Never add a branch that reveals whether an address exists.

## Gotchas

(Each is a recurring trap. One-liners by design.)

- **TS strict** — remove unused vars, don't prefix `_`.
- **`?:` catches only `undefined`, NOT `null`** — Python `None` → JSON `null` slips through `field?: number`. Use `field?: T | null` + `!= null`; default w/ `??`.
- **`/admin` in prod = React SPA**, not SQLAdmin. Edit `frontend/src/admin/pages/`, not `app/admin.py`.
- **Adding a Supplier field = 6 files**: model + alembic + Response/Create/Update + `to_dict` + TS type + List COLUMNS + FormPage. Use `/add-model-field` skill.
- **`SupplierResponse`/`CategoryResponse` are shared by public AND admin** — fields appear in unauthenticated routes. Use separate auth-gated endpoints for admin-only fields.
- **`response_model=SchemaX` silently strips computed attrs** — `obj.parts_count = N` stamps work locally; Pydantic's `from_attributes=True` drops them. Drop `response_model=` or add the field w/ default.
- **`routes/sponsors.py` + `routes/admin_sponsors.py` are symmetric `SponsorResponse` consumers** — any new field touches BOTH sites or Pydantic defaults silently to `None`.
- **Sponsor placement = write-side BLOCK + read-side filter (2026-06-22; was supersede)** — single-slot placements (Platinum on a top-level cat, Gold on a child) hold ONE active sponsor. `admin_sponsors._reject_if_slot_taken(...)` runs on POST+PATCH and rejects a 2nd active same-tier sponsor with **409** — the incumbent (oldest active) keeps the slot (was: `_supersede_existing_for_category` Expired the old one so the NEWEST won). `category_service` reads the single active sponsor (tier-filtered, Active OR NULL). To re-sell a slot the admin expires/removes the current sponsor first. **Exempt: Silver** (subcategory directory, multi) AND **keyword** (multi per keyword) — never blocked.
- **Sponsorships are the SINGLE source of truth (migration 011)** — the banner reads ACTIVE `sponsors` rows, tier-ordered, via `get_category_partners` (`/partners`), NOT a join flag. `CategorySupplier.is_featured`/`rank` DROPPED (pure association, cascade only). /admin/sponsors ↔ banner 1:1 — deleting a sponsor removes the company, no side-effect.
- **Sponsor tier↔placement matrix** — top-level cat (`parent_id IS NULL`) = **Platinum** only (single-slot); subcategory = **Gold** (single-slot) **+ Silver** (multi); keyword = Silver/Gold. "Featured" no longer exists (merged into Platinum). Enforced in THREE places that must agree: the Postgres trigger `sponsor_tier_placement_check` (catches raw SQL), `_validate_tier_placement`→422, and the admin `choosePlacement`. **Single-slot BLOCKS, it does not supersede**: `is_single_slot(tier, is_top_level)` — single home `app/models/sponsor.py`, imported by BOTH admin_sponsors and seed so the matrix cannot desync — gates `_reject_if_slot_taken`→409, and the incumbent (oldest active) keeps the slot. **The PATCH guard must ALSO fire on `status`→active**, or reactivating an Expired row into an occupied slot dodges a category/tier-only check and yields two active. Read-side picks OLDEST active (`created_at.asc`) to match. Migration 016's two partial unique indexes (`uq_active_{platinum,gold}_per_category`) are the un-bypassable DB backstop, and `seed.get_or_create_sponsor` is slot-aware so a reseed cannot crash them. Separately, `UNIQUE(supplier_id, category_id|keyword)` caps a supplier at one sponsorship per placement — a duplicate POST is a 409, not a second row.
- **`Sponsor.status` filters MUST treat NULL as Active** — legacy seed omits status. `status != 'Expired'` is UNKNOWN for NULL → silently skipped. Use `or_(status=='Active', status.is_(None))`.
- **Admin sponsor form = 3-way segmented placement** (`top-category|subcategory|keyword`) — `placementDerivedRef` MUST reset on `[id]` change (separate `useEffect`) or cross-edit nav keeps the prior bucket; all 3 buttons → `choosePlacement(p)`. Gating (2026-06-02): Category=`disabled={tier!=='Featured'}`, Subcategory+Keyword=`disabled={tier==='Featured'}`. Top-level + subcategory dropdowns are a custom `IconSelect` listbox (native `<select>` strips `<Icon>` markup) w/ `aria-activedescendant` a11y. Tier `<select>` `data-tier` → tier badges (`TIER_OPTION_STYLE`).
- **Sponsor XOR is Postgres-only** (SQLite skips CHECK) — enforce client-side in SponsorFormPage `validate()`/`buildSponsor()` AND server-side in router (422). Never both fields set or both empty.
- **Sponsor `tier` casing — normalize at EVERY read site** — admin emits TitleCase, legacy seed/DB store lowercase (`'platinum'`/`'gold'`); `tier` is a free string (no enum). Client-side: ALWAYS `@admin/services/sponsorTier.normalizeSponsorTier` (the single home + `SPONSOR_TIER_RANK` / `isActiveSponsor`(Active|null) / `countActiveSponsorsByTier`). ### Icon system

Public + admin both render Phosphor Light data icons via `<Icon name={x.icon} />` at `@shared/components/Icon.tsx` (regex guard `/^[a-z][a-z0-9-]*$/` no-ops on non-Phosphor strings). Font self-hosted at `frontend/public/fonts/phosphor-light/` (~1.2MB), loaded once in `frontend/index.html`. Admin **sidebar nav** uses Phosphor; topbar controls (Search/Bell/Plus/Menu) stay Lucide.

Names live in `api/app/db/seed.py` (15 + 75 = 90 strings). New category: kebab-case Phosphor name from https://phosphoricons.com — no `ph-` prefix. `Category.icon` is `String(40)` (alembic 005); regression asserts column metadata length ≥24 (SQLite ignores VARCHAR len).

**A Phosphor icon is ONE font character — its sub-parts cannot animate independently** — to animate a piece of a glyph (e.g. the Import card's falling-arrows "downloading" stream, 5852649), swap in an inline `<svg>` that redraws the same anatomy in separate nodes, `stroke="currentColor"` so the filled-card color cascade still applies, transform+opacity keyframes only, and a `prefers-reduced-motion` state that shows ONE static element (frozen stacked arrows at resting `opacity: 0` = invisible icon).

**Don't render `{x.icon}` as a raw text-node** — it'll display the literal name. Pre-commit guard:
```bash
grep -rn ">{[a-zA-Z_]*\.icon}<\|>{[a-zA-Z_]*\.category_icon}<" frontend/src --include="*.tsx"
# Empty = clean. Sweep frontend/src (not just /public).
```
`<option>` labels are HTML-text-only — drop any `${cat.icon}` prefix. When debugging icon rendering, screenshot — `getComputedStyle().content` is empty `""` for Phosphor's PUA glyphs in Chromium serializer even though the glyph paints.
